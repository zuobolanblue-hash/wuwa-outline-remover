# 去描边工具 · 分阶段测试方案（由最小到全量）

**核心原则**：每一级只多引入**一个新变量**；凡是"不开游戏就能验证"的都排在前面。
所以顺序是：先证明**数据安全**（离线、可逆），再证明**效果正确**（游戏内），最后才**上量**。

| 级 | 做什么 | 范围 | 开游戏 | 耗时 | 通过标准 |
|---|---|---|---|---|---|
| -1 | 兜底快照 | 1816 文件 / 629 MB | 否 | 7 秒 | 快照写入成功 |
| 0 | 自检 + 只读体检 | 416 个 Color.buf | 否 | 1.5 秒 | 异常 0 |
| 1 | 沙盒副本字节级验证 | 1 个 mod 副本 | 否 | 5 秒 | 15 项全过 |
| 2 | **单角色 · 单变体** | 1 个 mod | **是** | 5 分钟 | 身体黑边消失，别的角色不变 |
| 3 | 小批量 · 不同作者 | 3~5 个 mod | **是** | 15 分钟 | 都符合预期 |
| 4 | 一个分组 / 一个角色组 | 几十个 | **是** | 30 分钟 | 切变体不串味、不重复留档 |
| 5 | 全量 | 416 个 | 抽查 | 2 分钟 | 无失败项 + 原版角色仍有描边 |
| 6 | 全量回滚演练 | 416 个 | 否 | 1 分钟 | 与快照逐字节一致 |

> 第 **-1、0、1** 级现在已经跑过了（结果见文末基准数据），你从**第 2 级**开始就行。
> 第 6 级别跳——"全量改完能 100% 撤回来"才是敢用的前提。

---

## 第 -1 级 · 兜底快照（已完成）

**为什么先做这个**：这是唯一**不依赖工具自己存档**的安全网。工具的还原靠每个 mod 旁边的
`.nooutline.json` + `Color.buf.orig.<hash>.bak`；万一那两样丢了（手工删了、同步软件清了、
换机拷贝漏了），还能靠这份独立快照整体回滚。

```powershell
.\tools\wuwa-snapshot.ps1                 # 新建快照
.\tools\wuwa-snapshot.ps1 -Verify         # 只读比对（还原完用它确认）
.\tools\wuwa-snapshot.ps1 -RestoreAll     # 整体回滚（兜底最后手段）
.\tools\wuwa-snapshot.ps1 -RestoreAll -Exact   # 顺带删掉快照之后新产生的清单/原始档
```

快照只覆盖**工具的改动半径**：`Color.buf` + 所有 `.bak/.BAK/.bak_nooutline` + `*.nooutline.json`。

- ⚠️ 占 **629 MB**（`项目目录下的 _snapshots\<时间戳>`），测完觉得稳了可以删掉只留最新一份
- 只读，不动真实目录；`-RestoreAll` 永远不会删任何 `Color.buf`、也永远不会删 mod

**期望**：`SELFTEST OK`；`共 416 个 Color.buf；孤儿存档 0 个`；`异常 0`。三个数对不上就先别往下走。

**状态列里两种"不用管"的值**（都不会被写盘，也不会产生备份）：
- `空顶点色(无需处理)` / `R/G 全零(本就无描边)` —— 这份网格本来就没有描边数据（多为武器、发饰）
- `未使用顶点色(改了无效)` —— mod 的 ini 只声明贴图、没声明顶点缓冲，它画的是**游戏原版网格**，
  所以改它的 `Color.buf` 不会有任何效果（实测全树只有 1 个：`group_6\02 某角色 ww0000`）

## 第 1 级 · 沙盒副本字节级验证（已完成，15/15）

**这级是整套方案里唯一能证明"数据安全"的部分**，而且完全不用开游戏：把一个 mod 整个复制到
`项目目录下的 _test\ladder\`，在**副本**上打补丁 → 查字节 → 还原 → 逐字节比对。

```powershell
.\tools\wuwa-test.ps1              # 沙盒跑完自动清理
.\tools\wuwa-test.ps1 -Keep        # 想自己翻文件就保留沙盒
.\tools\wuwa-test.ps1 -Only 0      # 只跑只读的第 0 级
```

它验的是这几件事（全部自动判定）：

| 检查项 | 为什么重要 |
|---|---|
| R / G 通道全部归零 | 这就是"去掉描边"本身 |
| **B 通道逐字节不变** | B 是皮肤遮罩，碰了会毁皮肤 |
| A 通道逐字节不变 | `Alpha=keep` 时不该动头发相关通道 |
| 原始档 = 打补丁前的原文件 | 还原的"底"必须是真的原文件 |
| 重复打补丁 → 文件不再变、原始档仍只有 1 个 | 幂等，防止手滑点两次导致基准被覆盖 |
| 还原后 SHA1 与原始文件相同 | 逐字节无损，这是硬指标 |

## 第 2 级 · 游戏内单点（最小可见验证）

**对象只 1 个**：`_MANAGED_\group_6\05 某角色 ww0000 mod` —— 它已经打好补丁了
（状态 `已去描边`，原始档来源 `legacy`）。

1. 进游戏 → 用 WWMI 的菜单切到 **05 号变体**（就是那个 mod）
2. 按 **F10** 让 WWMI 重新加载
3. 看：身体轮廓、头发、肤色/贴图

| 现象 | 判断 | 动作 |
|---|---|---|
| 身体黑边消失、肤色正常、其它角色没变化 | ✅ 过 | 进第 3 级 |
| 身体干净，但**头发**还留一圈 | ⚠️ 预期内的分叉 | 把「头发描边怎么处理」改成 **`换成 0（连头发一起去）`**，只对这个 mod 再点一次 → F10 再看 |
| 贴图错乱 / 模型异常 / 游戏报错 | ❌ 停 | 选中该行 →「选中行 → 还原到选中版本」→ F10 确认恢复 → 把截图发我 |

**同时做一个负向对照**：找一个**没装 mod 的原版角色**看，**应该仍然有黑边**。
这证明工具没有越界去影响原版角色（原版角色的描边必须靠 shader 级 mod，顶点色方案管不到它）。

## 第 3 级 · 小批量 · 不同作者

**多引入一个变量**：不同作者、不同网格结构的 mod。

1. GUI 里勾上 **「只处理表格里选中的行」**
2. 选 **3~5 个不同角色**的 mod（建议含一个武器这类小网格 —— 它顶点数少、最容易看出异常）
3. 优先选你**实际在用**的那几个，这样效果好不好你一眼就知道
4. 打补丁 → 逐个进游戏看

**通过标准**：5 个都符合预期；表格里状态都变 `已去描边`，「我的备份」列都有值。

**失败处理**：那一行单独选中 →「选中行 → 还原到选中版本」，**不会影响其它 mod**。
这就是为什么第 3 级要"小批量 + 选中行"，而不是一上来全量。

## 第 4 级 · 一个分组全量

**多引入一个变量**：同一组内多个**互斥变体**同时被处理。

- 对象：整个 `_MANAGED_\group_6`（或你主用的角色组），点「MOD 目录」指到这个组即可
- 目的：证明切变体时**不串味**，而且**不会给同一个文件重复留档**

**通过标准**：
- 在组内切 2~3 个变体都正常
- `-History` 里每个 mod 的原始档没有重复项
- 再扫一次仍然显示 `已去描边`（幂等，不会越打越乱）

## 第 5 级 · 全量 416 个

**多引入一个变量**：数量。

1. GUI 里全选 → 打补丁（exe 约 1 秒）
2. `-Verify` 确认每个都留下了原始档、无异常
3. 游戏里抽查 **3~5 个不同角色** + **1 个原版角色**（必须还有黑边）

**记录一下耗时**（我这边基准：扫描 1.1 秒），以后更新游戏/mod 后可以对比是否异常变慢。

## 第 6 级 · 全量回滚演练

**这一步才叫"敢用"**：证明 416 个文件的全量改动可以 100% 撤销。

```powershell
# 1) GUI：「全部 → 还原成打补丁前」
# 2) 用独立快照验证逐字节一致：
.\tools\wuwa-snapshot.ps1 -Verify
```

**通过标准**：`VERIFY OK：和快照逐字节一致`。

## 失败了怎么办（撤退路线）

| 级别 | 典型现象 | 动作 |
|---|---|---|
| 1 | 字节校验 / 还原不一致 | **数据层问题，别碰真实目录**，把 `[FAIL]` 那几行发我 |
| 2 / 3 | 头发还留一圈、个别角色异常 | 效果问题 → 单 mod 还原后调「头发描边」选项 |
| 4 | 切变体异常 | 该组整体「还原成打补丁前」，组内层级可能特殊，发我 |
| 5 | 个别文件失败 | `-Verify` 定位是哪个；`-PurgeOrphans` 清无主存档 |
| 任意 | 想全部撤退 | `.\tools\wuwa-snapshot.ps1 -RestoreAll`（必要时加 `-Exact`） |

**两条铁律**
1. 第 1 级没过，绝对不要动真实目录。
2. 测试期间**别同时用 Wuwa Mod Fixer 打补丁**（两边都写 `Color.buf` 的还原档，边界情况说不清）。

## 附 B · 命令速查

```powershell
# 离线验证（第 0 + 1 级）
.\tools\wuwa-test.ps1
.\tools\wuwa-test.ps1 -Only 0

# 兜底快照
.\tools\wuwa-snapshot.ps1
.\tools\wuwa-snapshot.ps1 -Verify
.\tools\wuwa-snapshot.ps1 -RestoreAll

# 工具 CLI（不带动作参数 = 打补丁）
$exe = '.\WuwaOutlineTool.exe'
& $exe --cli -Path "<目录>"                 # 打补丁
& $exe --cli -Path "<目录>" -Status         # 看状态
& $exe --cli -Path "<目录>" -History        # 看还原点
& $exe --cli -Path "<目录>" -Verify         # 体检
& $exe --cli -Path "<目录>" -Restore        # 还原
& $exe --cli -Path "<目录>" -Alpha 0        # 连头发一起去
& $exe --cli -Path "<目录>" -DryRun         # 演练：只显示不改
& $exe --cli -Path "<目录>" -Status -Lang en  # 英文输出（界面右上角也能点着切）
```

> PowerShell 里收集 CLI 输出请用管道：`& $exe --cli ... -Status | Out-File r.txt -Encoding utf8`。
> 直接 `$o = & $exe ...` 拿不到东西 —— 那是 Windows 上 GUI 子系统程序的老毛病，不是工具的 bug。
